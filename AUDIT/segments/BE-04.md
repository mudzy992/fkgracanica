## Predlog P-B04-1 — zatvaranje draft leakova (backend-only, **0 FE/MOB izmjena**)

Ideja: **tiha autorizacija na @Public rutama** — JwtAuthGuard za @Public kontekst
umjesto čistog `true` radi `super.canActivate(...).pipe(catchError(() => of(true)))`
→ prijavljeni korisnik dobija `req.user`, anonimni prolazi kao prije (token
nevažeći/odsutan = i dalje javni pristup). time:

1. **news list** (`GET /news`): `status` param se poštuje SAMO uz `req.user`;
   anon → uvijek `PUBLISHED` (admin Writer/Moderator home rade bez izmjena —
   šalju Bearer; portal ionako koristi `/news/published`).
2. **news detail** (`GET /news/:id`): anon → 404 ako status ≠ PUBLISHED
   (CMS obrazac); admin edit radi (autentikovan) — FE netaknut.
3. **news comments** (`:newsId/comments` GET): anon → provjera da vijest
   ima status PUBLISHED, inače 404.
4. **gallery list** (`GET /gallery`): anon → uvijek `PUBLISHED` (barem
   mobile home postaje ispravan umjesto draft leak-a); `?status=PENDING`
   radi za prijavljene (ModeratorHome + mobile staff queue BEZ promjena).
5. **gallery detail** (`GET /gallery/:id`): **skinuti `@Public`** (svi pozivi
   su admin; portal/mobilni = slug) → anon 401.
6. **CMS** (`pages`, `pages/:slug`): `admin` flag vrijedi SAMO ako postoji
   `req.user` (tiha autorizacija) → `?admin=1` anonima = kao da ne postoji.

Rizici: guard postaje malo složeniji (unit testovi proširiti: silent-auth put +
da `?admin=1` anonima NE prolazi). Vidljivo: anon draft pristup → 404/401
(zatvaranje rupe).

## Predlog P-B04-2 — upload hardening

1. **Odbijanje ne-slika**: `saveFile`/interceptor prihvata SAMO `isImageMime(mimetype)`
   + ext allowlist `[jpg,jpeg,png,webp,avif,gif]` → inače 400 (trenutno NE
   postoji nijedna provjera; FE šalje isključivo slike — avatar + media).
2. **`limits: { fileSize: 16MB }`** u `FileInterceptor` → multer → **413**
   (trenutno: neograničen RAM po zahtjevu).
Vidljivo: preveliki/neslikovni uploadi → 413/400 (FE to ne šalje).
