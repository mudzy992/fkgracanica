## 1. Inventar i stanje pri auditu (prije implementacije)

- `frontend/package.json` ima Vitest + Testing Library, ali nema Playwright, axe ni coverage provider; nema `frontend/e2e/**` ni browser test skripte.
- `frontend/vitest.config.ts`: jsdom, 18 test fajlova, **69 testova**; nema konfiguracije coveragea ni praga. Ti testovi nisu browser E2E.
- `.github/workflows/ci.yml`: frontend build, Vitest, oxlint i `bundle-react`; postojeći `e2e` job je **backend** Jest + Postgres/Redis, nije web/browser E2E. CI nema axe ni budget ni frontend coverage gate.
- `frontend/src/router/{app-routes,public-layout-routes}.tsx`: 58 direktnih import linija stranica; u `frontend/src` nije nađen `React.lazy` / `lazy(`. `vite.config.ts` zadržava `resolve.dedupe` za React.
- `scripts/standards/bundle-react.mjs` provjerava različite verzije Reacta, ne veličinu bundlea; nije dokaz da su eliminisane dvije kopije **iste** verzije.
- `frontend/server/og-server.mjs` za browsere isporučuje statički `index.html`; za poznate crawlere injektuje share meta, ali ne dodaje robots direktivu.

### Browser/axe mjerenje (nije produkcija)

Pokrenut je lokalni produkcijski build u Chromium headless **153.0.8010.0**, sa Playwright Core 1.64.1 i axe 4.14.0, kroz privremeni harness i izolovane mock odgovore. Fontovi sa vanjske mreže su blokirani; CMS početna ima jednostavan hero, vijesti su prazne, a admin korisnik je lažan. Service worker je blokiran radi izolacije. Ovo je **mjerenje u tih nekoliko stanja**, ne audit svih produkcijskih podataka i ne dokaz full-stack rada.

| Stanje | Axe WCAG 2.0/2.1/2.2 A/AA: critical / serious |
|---|---|
| `/prijava`, desktop | 0 / 2 (kontrast) |
| `/admin`, desktop, mock login | 0 / 2 (kontrast, naziv dugmeta) |
| `/admin`, otvorena komandna paleta | 0 / 2 (isti nalazi na podlozi) |
| `/`, desktop, mock CMS | 0 / 2 (jezik, target-size) |
| `/vijesti`, desktop, prazna lista | 0 / 2 (jezik, target-size) |
| `/kontakt`, desktop | 0 / 2 (jezik, target-size) |
| `/placanje/monri`, gost | 0 / 3 (kontrast, jezik, target-size) |
| `/`, uski viewport, meni zatvoren | 0 / 0 |
| `/`, uski viewport, meni otvoren | 0 / 2 (kontrast, jezik) |

Isti elementi se ponavljaju na više stranica: redovi **nisu nezavisni zbir defekata**. Ručno potvrđeno: gost `/admin` → `/prijava`; neuspjela i uspješna mock prijava; otvaranje admin palete; nedostajuće labele/kontrola i Escape u meniju. Nije bilo `pageerror`. Koriste se axe pravila s tagovima WCAG 2.0/2.1/2.2 A/AA; automatski test ne zamjenjuje ručnu WCAG provjeru.

## 31. P-FE06-23 — odobrena FE mitigacija djelimičnog foto-unosa

- Sekvencijalni POST ne pokušava se automatski ponovo (30 s timeout); završetak
  i greška označe galerijske queryje zastarjelim bez paralelnog slijepog
  refetcha. Potom zaseban GET detalja (15 s, `Cache-Control: no-cache`) mora
  uspjeti i sadržavati identitet, naslov i valjanu listu foto ID-jeva/putanja.
  Stariji detaljni query se poništava prije potvrde, da ne prepiše novi rezultat.
- Pojedinačni izbor i uvoz svih stranica mape koriste isti tok. Klijent filtrira
  već vidljive putanje i ponovljene putanje u izboru. Pristupačna BS/EN poruka
  upozorava da su neke slike možda već dodane i da se kod neizvjesnog odgovora
  mogu pojaviti kasnije. Ako GET ne uspije ili nema valjan detalj, novo
  dodavanje ostaje blokirano; ručni „Osvježi galeriju” šalje **samo GET**, a
  novi izbor/uvoz prepušta korisniku. Greška čitanja mape prijavi da nijedan
  POST nije poslan. Nema automatskog brisanja, ponovnog POST-a ni deduplikacije
  postojećih redova.
- Zaključavanje i upozorenje čuvaju se po galeriji u istom QueryClientu i
  preživljavaju SPA ponovno montiranje; ne dijele se između tabova, novih
  sesija ili nakon reloada. Ponovno učitavanje mora dohvatiti detalj prije
  slanja ako ga cache nema. Istovremeni editori ili server koji dovrši POST
  **nakon** kontrolnog GET-a i dalje mogu stvoriti duplikate; FE refetch nije
  exactly-once. Serverska idempotentnost/unique ostaje zasebna odluka.
- Osvježavanje detalja čuva nespremljeni naslov i opis, uključujući oporavak
  nakon neuspjelog prvog GET-a; čista polja se mogu osvježiti.
- Red/green: prethodna verzija u Chromium mocku pada zbog nedostajućeg alerta
  i neuhvaćenog 500. Nakon ispravke **10/10 unit** i **7/7 namjenskih browser**
  testova; ukupni izolovani browser/axe **83/83** (uključuje uski web viewport,

  neuspjeli GET i ručni retry, mapu, čekanje GET-a na uspjehu, staru query trku,

## 32. B-FE06-27 — trka reda za upload u medijsku biblioteku

Ovo je **odvojeno od P-FE06-23** i odnosi se na upload izabranih fajlova u
medijsku biblioteku (`MediaPage` / `useMediaUploadQueue`), ne na povezivanje
postojećih medija s galerijom. `isRunning` se izvodi iz statusa stavki, a
`runningRef` ostaje true dok završava invalidacija media queryja. `enqueue`
prvo zamijeni vidljivi red, a tek potom `processQueue` odbije novi red ako je
`runningRef` već true. Četverosekundni timer prethodnog reda ne poništava se
pri novom redu i može očistiti novi aktivni red.

- Izolovana React Query proba: prvi mock upload završi, a invalidacija je
  namjerno odgođena; status prijavi `isRunning=false`, drugi odabir postane
  `pending`, ali drugi POST nije poslan.
- Izolovani Chromium/mock 1/1: pravi file chooser i sintetički `first.jpg`
  pošalje se; dok `GET /media/assets` čeka, Upload se ponovo omogući. Izbor
  `second.jpg` pokaže `Upload 0/1`, ali POST se ne šalje; nakon timera
  indikator nestane.
- Druga Chromium/mock proba 1/1: nakon prvog uspješnog reda `second.jpg`
  ostaje na namjerno odgođenom POST-u; stari timer nakon četiri sekunde briše
  napredak i omogućava Upload. Odabrani `third.jpg` ne šalje se. Svi fajlovi
  i server su sintetički; nema stvarne produkcijske mreže, upisa ili dokaza da
  se problem dogodio u produkciji. **Izvorni korisnički fajl nije obrisan**,
  ali namjeravani upload može izostati bez jasne poruke.
